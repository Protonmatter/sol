# RFC 0007: Dynamic illustrative Sun and preserved source playback

- Status: Accepted
- Authors: Min Kang, Codex
- Created: 2026-09-23
- Target: Local implementation candidate; no production promotion
- Requirements: `SOL-SUN-001` through `SOL-SUN-018`

## Summary

The user authorized the detailed dynamic-Sun plan and Blender installation with
"get blender and do what you need to get this implemented." Use a complete,
explicitly illustrative three-dimensional Sun for isolated Solar System inspection.
Preserve the original source-facing observation and legacy reference modes.
Acceptance records the authorized direction; it does not imply merged code,
scientific calibration, physical-iPhone qualification, or publication.

## Context

The supplied screenshots show an opaque, nearly featureless hemisphere alongside
a mapped AIA image. Rotating a single observed disk cannot provide an observed
far side. Static decorative arches also do not demonstrate solar evolution.
The research and immutable implementation plan are in
[the dynamic-Sun plan](../plans/2026-09-23-dynamic-sun/README.md).

## Requirements

`SOL-SUN-001` through `SOL-SUN-018` preserve the plan's SUN-01 through SUN-18
acceptance statements and evidence mapping in `docs/requirements.json`.
The display MUST identify modeled and observed content, maintain independent
clocks, preserve source provenance, enforce bounded resource ownership, and
retain existing scientific engine interfaces. Qualification MUST remain distinct
from implemented-local behavior.

## Design

Rust supplies deterministic surface recipes, potential magnetic-field solutions,
field-line geometry and an additive appearance ABI. Offline tools prepare
hash-bound quiet/active scenario assets. The browser uses an opaque emissive
surface, a diffuse volume and analytic Gaussian strand integrals. Scalar emission
is accumulated before the selected palette and final display transform.

The current browser uses initial PFSS connectivity with differential advection
and finite local pulses. Precomputed geometry keys remain reference-authoring
products; this browser path does not solve evolving magnetic connectivity.
Optional cool material is a declared thin-sheet transfer approximation; a
user-triggered eruption is a finite educational event. Neither is measured plasma
or a magnetohydrodynamic simulation. A separate 121-frame AIA browse sequence
retains each displayed frame's timestamp, hashes, source metadata and unqualified
provider quality flag. It has no invented intermediate frames or far-side map.

Blender consumes the same source-hashed numerical geometry and field products.
CPU Cycles fixtures establish bounded transfer comparisons; beauty images alone
do not qualify the physical model. See [the implementation guide](../DYNAMIC_SUN.md).

## UX and accessibility

The isolated Sun provides visible/EUV selection, pause, seek, rate, scenario,
detail, corona, cool-plasma, explicit eruption, whole-Sun and close-up controls.
Reduced motion and backgrounding pause playback. Source playback remains a
separate explicit action. Interior cutaway is labeled schematic. The Sun's central
name label is omitted in inspection. Responsive desktop emulation is not a
physical Safari/iPhone test.

## Security and privacy

Normal rendering fetches only bounded same-origin immutable assets. Readers reject
escaping paths, redirects, size/hash mismatches, unsupported units/layouts and
duplicate JSON keys. Explicit source preparation retains provenance separately.
Blender is a portable per-user official binary, verified against its published
SHA-256. No credentials, telemetry or background service is added.

## Alternatives

Repeating a single source disk around the globe would fabricate observational
coverage. A smoke/fire simulation would supply attractive but inappropriate solar
physics. Full MHD and instrument response synthesis require a separate scientific
data and compute project. This implementation uses a bounded illustrative model
and keeps genuine source-image playback available.

## Risks

The coronal intensity is relative, and the EUV palette is assigned. Fine structure
is statistical. PFSS has no currents or self-consistent heating. Desktop numerical
checks do not establish mobile performance or observational realism. Blender's
coincident volume limitation and device-specific float behavior require explicit
qualification evidence. GPU failures retain a labeled simplified display.

## Acceptance criteria

Every SUN requirement retains its linked implementation and checks. Local tests,
staged browser evidence and Blender receipts are recorded independently. Physical
iPhone, long-duration thermal behavior, matched full-scene image parity and
scientific visual acceptance remain open until actual evidence exists. No passing
unit suite substitutes for these gates.

## Validation

Use repository Rust, Node, Python, type and governance checks; actual WebGL2
transfer/strand/cool-plasma fixtures; staged application/source-playback tests;
and Blender CPU transfer/atlas/Gaussian receipts. Follow the unchanged
[test matrix](../plans/2026-09-23-dynamic-sun/test-matrix.md).

## Rollout and rollback

This is an isolated uncommitted candidate. There is no production deployment.
Retain legacy modes and the original dirty checkout. Validate a complete staged
artifact before any later authorized promotion; rollback uses a prior complete
artifact, never individual shader or manifest substitution. Local reproduction
and artifacts are described in the implementation guide.

## Documentation

The original research plan remains unchanged. This RFC, requirements traceability,
implementation guide, status and final evidence distinguish implemented features
from remaining qualification gates.
