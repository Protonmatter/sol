# RFC 0000: Short descriptive title

- Status: Draft
- Authors: GitHub handles or names
- Created: YYYY-MM-DD
- Target: release, milestone, or none
- Requirements: `SOL-AREA-000`

## Summary

State the decision and user outcome in a few sentences.

## Context

Describe the problem, current behavior, evidence, scope, and non-goals.

## Requirements

Use stable `SOL-*` IDs and BCP 14 language. Add new records to
`../requirements.json` before implementation.

## Design

Describe interfaces, data flow, states, trust boundaries, compatibility, and affected
components.

## UX and accessibility

Describe the primary workflow, disclosure levels, keyboard/focus/touch behavior, responsive
states, feedback, errors, and manual validation.

## Security and privacy

Identify attacker-controlled inputs, protected assets, remote data, consent, dependency
risk, and fail-closed behavior.

## Alternatives

Record viable alternatives and why they were not selected.

## Risks

List technical, scientific, product, operational, accessibility, and delivery risks with
mitigations.

## Acceptance criteria

Write observable outcomes and identify the test layer for each.

## Validation

List unit, contract, integration, browser, visual, deterministic, accuracy, coverage, and
manual checks that apply.

## Rollout and rollback

Describe compatibility, migration, observability, release sequence, and the safe rollback.

## Documentation

List README, specifications, requirements, instructions, operations, status, and user help
that must change.
